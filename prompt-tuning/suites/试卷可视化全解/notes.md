# 失败样例库：试卷可视化全解（v0 → v1）

记录格式：`[版本] 案例/题位 — 问题 — 证据 — 修复`。
本文件只记**实测到的问题**，不记猜测。原始数据在 `runs/试卷可视化全解/work/`（不入库）。

案例集（真题切片，源自 2022 年全国甲卷，含参考答案）：
`c1_reading_b`（含听力在前，4 题）、`c2_reading_c`（4 题）、`c3_cloze7`（七选五 5 空 7 选）、
`c4_cloze_blank`（完形节选 5 空）、`c5_grammar`（语法填空 5 空，无选项）、`c6_writing`（书面表达）、
`c7_reading_a_nokey`（应用文 3 题，材料未附答案）。

## v0 基线（生产版，16.8KB）实测

**跑法**：7 个案例 × 迁移档位 1（+ c1/c2 档位 2），共 9 份。

### 协议 / 照录 / 答案一致性：基本全绿

- `@@TAG@@` 格式、标签取值位置（单行值/多行内容/PASSAGE_DEF 混合）、题数=题块数、题号照录、
  QTYPE 与 OPTIONS 一致、语篇"只声明一次 + 按编号引用"、迁移块数、写作题分支：**9 份全部 0 问题**。
- 答案与材料所附答案**逐题一致**（26 道选择题，0 处不一致）。
- 听力自动跳过且题号不重排：`c1` 首题为 24（不是 1），正确。
- 唯一照录缺陷：`[c7] Q22` — EVIDENCE 把 Glee Club 段的两句拼成一条，**跳过了中间那句**
  （`It is hard to name a comedy star who hasn't been on the stage here.`）。
  学生按证据回原文找不到连续段落 → 投影时会被学生当场发现。

### 迁移题：问题集中在这里（与用户最初的抱怨同源）

| 问题 | 证据 |
|---|---|
| **选项池形式失真** | `[c3]` 七选五 5 空 7 共享选项，迁移全部退化为"单空四选一"：5/5 块（`transfer_pool_mismatch`）。原题型最难的跨空排除被整个丢掉 |
| **换皮（同脚本换词）** | 决策模型判定 26 个迁移块中 **81%** 属换皮/复述（`transfer_copy` 均值 0.66，反向指标 >0.5 即判换皮）；例：`[c7] Q22` 迁移是把"场馆功能定位"换成另一个场馆；`[c1] Q24` 原题"鹦鹉用工具取坚果"→迁移"大象用竹棍取水果"，同一脚本 |
| **迷惑性不足** | `transfer_deception` 问题率 **81%**（均值 0.39）：干扰项一眼可排除。例：`[c2] Q28` 迁移把 `take the plunge` 换成 `take the leap`，正确项"Make a risky but determined start"是叙事的透明转述，另三项（放弃爱好／回到旧职／请教他人）与文本无关 |
| **可归纳的字母规律** | `[c2]` 4 道迁移答案全为 A（`ans_position`）；`[c3]` A 占 3/5 |
| **长度/措辞线索** | `[c3]` 正确项是最长项的比例 60%（≥50% 即可能被猜）；1 处正确项含绝对化措辞 |
| **迁移语篇词数不足** | 3 处 77–79 词（要求 80–120） |

### 同类问题的性质判断

`原题四维`（答案唯一性、证据充分性、易错点具体性/独立性、范式可套用性、推理与事实一致）
六项问题率**全部为 0%**（n=26）。也就是说 v0 的**讲解部分质量很高，迁移题是短板**——
与"错题迁移"当初的病灶完全一致，所以修复直接沿用那套已被验证的机制（v17）。

## v1：从「智能错题迁移 v17」移植迁移题机制

改动方式：**移植**，不是重新发明。逐条对应关系：

| v17 的机制 | 移植到本 prompt 的形态 |
|---|---|
| 出题流程第 1 步「先写方法论并锁定」 | 「先写 `PATTERN_NAME`/`PATTERN_STEPS` 并锁定」；范式是迁移题的契约，写完不许回头改；范式示例只能取自原题 |
| 写下学生默认"错误直觉"清单，干扰项从清单取材 | 原样移植（长选项更对／绝对化必错／原词复现就是答案／排除最荒谬的剩中间） |
| 干扰项套路分配表（五种错法轮换） | 原样移植（引语复现／过度夸大／编造动机／半对项／真而无关） |
| 命题骨架分配表（≥3 种骨架、三拍骨架 ≤2 次、无解释反推题、多段落语篇） | 原样移植 |
| 远迁移"去路标"要求 | 原样移植（隐去转折词／时间状语／本人引语，改写成需推理的形式） |
| 半对干扰项、正确项与证据隔一步推理、定义句不算证据、反证句只可否决 | 原样移植 |
| 双通道验证（凭应试直觉必须错或犹豫） | 原样移植 |
| 可归纳性审查（防"邪修"）：考点词隐性替换＋角色双向、正确项原型轮换、字母/位置机会均等、选项长度均衡 | 原样移植（角色双向按"同一份输出内的迁移题之间"执行） |
| 答案多样性（语法填空主动侧 ≥3 题） | 原样移植 |
| 题量守卫（"至少 N 题"在小样本下要可定义） | 新增定义：迁移块总数＝题数 × `{{transfer_count}}`，配额均带"≥5 时"守卫 |
| 方法论泄题禁令 | 移植为「范式不泄题」＋新增机械检查 `pattern_leak` |
| —（v17 无此问题） | 本 prompt 特有：**选项池形式必须与原题一致**（七选五不得退化成四选一）、**EVIDENCE 必须连续原文**（禁止跨句拼接） |

## v2：补移植两段（+2.3KB）——以及一处自相矛盾

**触发**：v1 的 `pattern_reusable` 从 0% 涨到 18%，且 `transfer_copy` 仍留 24%。逐条读失败单元后定位到根因：

- 范式被写成**原题专属**（`[c3] Q37` 范式写成"先读小标题：Chopstick Rules"、"找代词 them 的指代对象：chopsticks"），
  迁移题换了语境自然套不上 → 这正是 v17 反复强调的"方法论要写到第一步看什么、第二步排什么"的颗粒度问题。
- 迁移题**照抄框架句**（`[c5] Q61` 原题 `as a first step 61 (journey)…` → 迁移 `As a first step ___ (test)…`）：
  v17 的**原题指纹禁令**（实词/场景/句式/选项四类）我只移植了"换域不是换词"这一层，没搬整段。
- 另外，v1 里我引入的"范式写完即锁定、只许改题"与 v0 既有的"迁移题走不通就修正范式"**自相矛盾**，
  这条锁定是我自己加的、v17 里没有，属于误加。

v2 的改动：① 删掉自相矛盾的"锁定"，改为"范式先写、可修，但不许改成类别映射"；
② 新增「范式必须不依赖原题具体内容」；③ 整段移植**原题指纹禁令**（并补本 prompt 特有的辨析：考点语法结构要保真、框句必须重新设计）；
④ 自检清单补指纹与范式通用性两条。

**v2 实测**：机械 11 项、换皮 24%、迷惑性 65%、`pattern_reusable` 9%（回归减半）。

### 复现轮：把噪声底量出来

v2 单轮看起来比 v1 差（11 项 vs 3 项），但每个案例只有 1 份输出。用**同一份 v2 prompt 重跑一轮**（`v2_r2`）后发现：

- 机械问题 11 vs 13；换皮 24% vs 26%；迷惑性 65% vs 62% —— **同 prompt 波动就有这么大**。
- 结论：**n=42 时 ±10 个百分点以内的差异不能当结论**。此后所有版本判断都以此为准。

同时复现轮抓到两处**规则歧义**（不是"规则不够多"）：

| 漂移 | 实测 | 根因 |
|---|---|---|
| 七选五迁移把选项池从 7 项缩成 5 项 | v2 轮 5/5 块；v2_r2 轮 0/5 | "同规模共享选项池"里的"同规模"有歧义 |
| 语法填空迁移挖成 3 个空 | v2_r2 轮 5/5 块（第 3 空考定语从句 `who`，考点漂移） | "共享池要保真"被过度泛化到无选项题型 |

## v3：只做两处精确化，不加新规则

① 共享池迁移的选项池"与原题项数相同、多余项数一致"；
② `blank` 类型迁移**只挖一个空**，多空共享池规则只适用于原题本身带共享池的题（原卷里语法填空每个空本来就是独立一题）。
配套加了机械检查 `transfer_blank_multi`（`_{2,}` 或 `数字 (` 计数 >1 即报）。

**v3 实测（两轮）**：机械 3 项 / 5 项；换皮 21% / 31%；迷惑性 60% / 68%；多空漂移 0 / 0；`pattern_reusable` 12% / 15%。

判定：v1/v2/v3 在换皮与迷惑性上**没有可辨识差异**（全在噪声内），v3 胜在把两处边界漂移清零、且 `pattern_reusable` 优于 v1。故定稿 v3。

## 残留与代价（完整数据见 report.md）

1. **范式可套用性下降是真回归**：v0 0/34，移植后五轮合并 25/170 ≈ 14.7%（单侧 p≈0.005）。
   机制：迁移题被推得更远（换域/去路标/共享池），三步范式不再机械等价于答案。属取舍，不是 bug。
2. **整体观感仍偏向 v0**：盲评合并 2:7（n=9，p≈0.18，方向一致但未显著）。最可能是体积代价（16.8KB → 26.6KB）。
3. **三处"自查不可靠"残留**：迁移语篇 <80 词（1–4 处）、正确项是最长项（50%→50%/41%，**未改善**）、
   证据跨句拼接（0–2 处，**未根治**）。这三类应交给生成后门禁（`vp_check.py` 已能检出），不要再往 prompt 里加自查规则。
4. **仪器缺陷已修**：评分器原先对语法填空题的迁移问"错误选项有没有吸引力"——该题型无选项，问题不成立；
   现按题型分型提问并用 `SCHEMA` 后缀隔离旧缓存。
5. **工具缺陷已修**：`gen.py` 曾把 0 字节输出当成功落盘（推理模型把预算烧在 reasoning 上、正文为空），重跑还会跳过；
   现当失败重试。

## 待验证 / 遗留

- 整卷一次性生成仍未验证：30+ 题的输出量超出单次调用预算（用户已知"基本一次跑不完"）。
  本次评测一律用切片输入，`@@END_Q@@` 的逐题落盘语义因此未被覆盖。
- 切片输入的补号无锚点：`c6_writing` 材料只有写作一题、卷面未印题号，模型补为 1。
  整卷输入时才有"接着上一题顺延"的锚点，故不校验此项，仅记录。
- 体积红线：prompt 里约 8KB 是 `@@TAG@@` 输出契约（前端解析器接口，不能删）。
  真正瘦身的唯一方向是把契约移到服务端格式化层，属工程改动。


## v4：Goodhart 代偿机制移植（2026-09-29，自智能错题迁移 v18 移植）

**背景**：用户在独立工具实测发现两个新问题（迁移题与错因脱钩；模型为钉死答案写显性硬否定句、剧情套固定公式——古德哈特代偿），指示先在独立工具跑通再移植到本 prompt。

**新仪器**：`vp_goodhart.py`（point_same / trap_live / hard_negation / template_plot 四个 noul 判定，state 含 TRANSFER_EXPL 钓鱼路径——不含 EXPL 时 trap_live 被系统性低估，v3 由 29% 虚报为 50% 失败率）。

**v3 基线（jev，EXPL 口径，42 迁移块）**：point_same 0.88/10% 失败、trap_live 0.54/29%、hard_negation 24%、template_plot 38%。c3_cloze7 的 point_same（0.60）本就是全 suite 最弱——v3 的七选五迁移语篇已退化为"规则罗列体"（museum rules 一类），各空逻辑功能同质，跨空排除名存实亡。

**v4 移植内容**：① 硬否定禁令（正面证据原则＋全组 ≤2 处＋"回去重设干扰项"泄压阀＋半对项长度义务）；② 双通道→三通道（新增"按 @@PITFALLS@@ 最典型易错习惯做必须做错"）；③ 范式≠剧情模板；④ 分配表禁印进输出＋骨架"无本人解释"配额设上下界（至少 1 且至多一半）＋套路表按题型分池。
**首轮移植后暴露两个回归**：c3 point_same 掉到 0.23（规则罗列体恶化）；trap_live 无改善。→ 追加两条：⑤ 共享池迁移禁用规则罗列体、空白逻辑功能至少三种；⑥ 干扰项钓鱼路径必须挂到 @@PITFALLS@@ 某一条上，挂不上重写。

**v4 终版（jev，EXPL 口径，26 迁移块）vs v3**：
| 指标 | v3 | v4 |
|---|---|---|
| trap_live 失败率 | 29% | **8%**（钓鱼路径挂 PITFALLS 生效） |
| hard_negation | 24% | **8%** |
| template_plot | 38% | 35%（噪声内持平；首轮样本曾到 19%） |
| point_same 失败率 | 10% | 12%（持平；c3 七选五弱项仍在，未见恶化） |
| 机械检查 | 3 问题 | 4 问题（transfer_len ×3＋length_cue ×1，均为已知残留类） |

**残留与下一步**：① c3 七选五迁移的逻辑功能多样性仍脆（两轮采样一次 0.23 一次可接受），建议后端对共享池迁移加"空白功能唯一性"机械门禁；② point_same/trap_live 的判定 n 小（26 块），结论按 ±10pt 噪声底解读；③ 未跑 vp 盲评 A/B（机制已在独立 suite 盲评过，且 vp 盲评载荷大）。
