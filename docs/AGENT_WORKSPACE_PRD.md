# NeoBangX Agent 工作台产品需求

版本：1.0 实现基线（已补充管理端 MCP 决策）  
日期：2026-10-25  
入口：`/agent`  
用途：作为 Agent 模式重写的产品基线，先确定用户体验、功能边界和验收方式，再制定技术设计。

## 1 产品定位与目标

Agent 工作台面向需要连续完成备课、试卷分析、题目检索和材料加工的教师。用户说明目标，提供材料，查看并调整提示词和可用工具；Agent 在这些约束下开展工作，用户可以随时了解进展、补充要求、检查依据和修改成果。

这是独立的任务工作空间。普通工具页继续服务一次输入、一次输出的快速任务；复杂任务进入 `/agent`。从普通工具进入时可以带入材料及该工具的提示词，进入后仍能修改。用户也可以直接访问 `/agent`，从空白任务开始。

本次设计确定的方向：

- 提示词是主界面中的可读、可编辑内容。开源提示词不设置人为的查看门槛。
- 工具可选择、配置和复用，并能扩展到题库、正则查找和网络搜索等能力。
- 执行流程由任务需要决定，允许检索、分析、检查、生成和修订；不要求每个任务都经历相同的流水线。
- 成果、材料、提示词和过程分别组织。长思考全文可访问，不能通过删除内容换取流畅。
- 大屏、小屏笔记本、平板和手机都能完成核心任务，手机不能只有查看能力。

文中具体默认值与发布批次为本版产品建议。计费、数据保留和第三方接入范围在第 15 节单独列出。

## 2 核心场景

| 场景 | 用户操作 | 应获得的体验 |
| --- | --- | --- |
| 快速备课 | 选择现成提示词，上传试卷，开始任务 | 不必先理解 Agent 配置；能看到正在使用的提示词，随时修改 |
| 精细调整 | 修改取材范围、教学重点和输出要求 | 明确知道修改只影响本任务，或主动另存为个人模板 |
| 基于证据分析 | 要求分析易错点，启用材料检索 | 每个关键引用可回到材料位置，来源不足时明确说明 |
| 检索题目 | 启用题库，限定年份、地区、题型 | 找到有出处的题目；无结果时如实报告，不把生成题伪装成真题 |
| 使用外部信息 | 启用网络搜索 | 可见搜索词、来源与引用，能区分材料原文和外部资料 |
| 执行中纠偏 | 补充“只处理前两篇”或关闭某工具 | 补充要求有接收和生效状态，不需要重新粘贴整套材料 |
| 审阅与修改 | 查看质检意见，要求修改某一处 | 可比较新旧版本；错误意见可以忽略，旧成果始终可找回 |
| 换设备继续 | 电脑开始任务，手机查看或继续操作 | 登录同一身份后恢复任务、已保存配置和成果；关闭网页不取消任务 |

## 3 信息架构

工作台使用四类对象，界面中保持名称一致。

| 对象 | 用户理解 | 主要操作 |
| --- | --- | --- |
| 任务 | 围绕一个目标持续进行的工作 | 新建、继续、停止、重命名、复制、删除 |
| 提示词 | 告诉 Agent 做什么、如何取舍的可编辑说明 | 查看、修改、比较、恢复模板版本、另存 |
| 工具 | Agent 可调用的具体能力 | 启停、配置、查看说明、试运行、保存个人配置 |
| 成果 | 可独立阅读、编辑、导出的文档或内容 | 查看、手动编辑、比较版本、采用、导出 |

一个任务可以包含多轮执行、多个材料和多个成果。一次“继续”产生新的执行记录，不覆盖已有历史。任务记录中保留使用过的提示词、工具配置、材料版本与成果版本之间的对应关系。

建议页面路径：`/agent` 为任务入口，`/agent/tasks/:id` 为可恢复的任务地址；个人提示词和工具库从工作台导航打开。地址可定位任务，但不意味着公开分享。

## 4 页面布局

### 4.1 大屏工作台

大屏采用可调宽度的三栏布局：左侧任务导航，中间对话与进度，右侧工作区。右侧默认获得较大面积，用于阅读和编辑长内容。

左侧包含新任务、任务搜索、最近任务、我的提示词、工具库和返回普通工具。中间承载任务目标、用户补充、Agent 的进展说明、工具活动及消息输入。右侧设固定顺序的“提示词／材料／工具／成果”页签。

新任务默认展示提示词页签，编辑器直接可见。选择模板后立即展示模板内容；不要求先运行一次才能看见提示词。成果产生后显示可打开的成果入口。如果用户正在编辑或阅读其他内容，不自动抢走当前页签和焦点。

各区可独立收起；对话、提示词、成果都有“专注”入口，可以占满工作区域。列宽在合理范围内记忆；窗口变窄时自动切换布局，不把内容强行挤到最小宽度以下。

（早期布局概念稿未随仓库提交，`docs/design/` 目前为空；布局以大屏三栏的实际实现与本节文字为准。）

### 4.2 按可用宽度重排

以下为初始布局断点，依据内容最小可用宽度在原型测试中调整。使用 CSS 可用视口宽度，不以设备型号判断；浏览器缩放、系统缩放和分屏都计入适配。

| 可用宽度 | 默认布局 | 导航与切换 |
| --- | --- | --- |
| ≥1440 CSS px | 任务列表、对话、工作区三栏 | 列宽可调，任一工作区可专注展开 |
| 1100–1439 CSS px | 对话与工作区两栏，任务列表收起 | 窄导航栏打开任务抽屉；两栏均可独占窗口 |
| 768–1099 CSS px | 单主区域，默认不并排展示长文和对话 | 顶部切换“对话／工作区”，任务列表为抽屉 |
| <768 CSS px | 手机单栏，所有编辑与阅读占满内容宽度 | 顶部“对话／工作区”切换，任务抽屉从菜单打开 |

两栏模式保证对话区至少约 320 px、文档区至少约 480 px；达不到时切到单区。小屏笔记本同时考虑高度：减少无效上下留白，工具栏保持一行主操作，次要动作进入菜单；不通过缩小正文来容纳更多面板。

（布局概念稿未随仓库提交；断点与切换行为以本节表格为准。）

### 4.3 手机的完整工作流

手机新任务默认进入工作区。顶部是简洁的任务目标和材料入口，下方为提示词编辑器与工作区页签，底部为“开始任务”。目标较长时可进入全屏编辑，返回后保留正文与光标位置。

运行后，“对话”显示进度和消息输入；“工作区”显示提示词、材料、工具或成果。两个区域保留各自滚动位置，切换不重新加载整份内容。后台有新成果或等待补充时，通过标签和状态提示通知，不强制切屏。

手机上的提示词编辑、工具配置、材料阅读和版本比较采用整页视图，避免多层小弹窗。成果版本差异使用同一列的新增、删除和修改标记，可切换原稿／候选稿；不并排缩小两份文档。

正文与普通段落自然换行。具有明确字段的简单表格可以切换为逐条阅读视图，保留完整单元格和表头关系；合并单元格、多层表头等复杂表格保留原结构，在局部容器横向滚动，并提供横屏或全屏入口。任何适配都不能重写或省略原始内容。

### 4.4 输入与无障碍细节

- 软键盘出现时，只保留当前编辑所需操作；底部输入框或按钮跟随可见视口，不遮挡光标、最后一行和保存状态。
- 编辑提示词时不叠加聊天输入框；自动保存不打断中文输入法组合过程。
- 手机按钮建议至少 44 × 44 CSS px，关键操作不能只靠悬停；适配底部安全区与横竖屏切换。
- 桌面支持键盘导航、明确焦点和分隔条键盘调整。状态不能仅靠颜色区分。
- 浏览器前进、返回能回到上一工作视图，避免意外退出整个任务；关闭抽屉后焦点回到入口。
- 200% 缩放和窄屏下页面主体不出现横向溢出，局部表格与代码块除外。

两张图片是布局概念稿，图中模型名、示例资料、按钮细节不作为已确定的功能或数据。分享入口属于后续范围；首版不默认公开任务。

### 4.5 视觉语言与组件

工作台与普通工具页共用同一套设计系统，不另立配色：

- 主题：读取 `localStorage.nbx_theme`，支持宣纸、青瓷、曜石、墨翠、悠空（白昼/星夜）五种；悠空按 6:00–22:00 自动切换，也接受 `#sky=day|night` 强制。顶栏提供主题切换。
- 材质：面板使用主题变量（`--panel` / `--border` / `--accent` / `--shadow`）与同一套圆角、间距；大块面板不做背景模糊，只有抽屉、菜单、弹窗与提示条使用玻璃材质，避免移动端多块大面板同时模糊。
- 控件：下拉、复选框、数字框、滑块、文件上传、折叠区、弹窗与滚动条全部自绘，保留原生语义元素（`select`、`input`、`details`、`dialog`）以便无障碍与系统选择器；不使用浏览器默认外观。
- 状态：运行、完成、失败、等待都有文字 + 图标 + 颜色三重表达，不只靠颜色区分。
- 信息密度：正文 13–15 px，辅助信息 10–12 px；步骤卡以左侧节点与竖线表示执行顺序，进行中的步骤有节点呼吸提示（减少动效偏好下关闭）。
- 入口：普通工具页侧栏 Logo 下方是一张入口卡（渐变图标块、两行说明、箭头），有当前工具时再露出“带入当前材料与提示词”次级动作；入口位置不占用工具列表。

## 5 从进入页面到开始执行

用户可以从空白任务、官方提示词模板、个人模板或普通工具的“在 Agent 中继续”进入。迁移入口带入材料与模板副本，不改普通工具的原记录。

准备区提供目标输入、粘贴或上传材料、提示词编辑、工具选择和模型选择。模板预置合理的工具组合，用户无需配置所有字段就能开始。模型不可用、材料解析失败、必需参数缺失等问题在开始前明确指出；仅有可选工具不可用时，允许移除后继续。

材料解析后可预览全文，显示文件名称、解析状态与可定位的章节或页码。页码无法可靠获取时使用段落或片段位置，不伪造精确定位。原始上传文件与可读材料分别保存，解析失败不当作空材料继续生成。

“开始任务”会固定本轮的提示词、材料、工具和模型版本。重复点击和网络重试只创建同一轮执行。用户立即看到已创建的任务和接收状态；排队、模型处理中与网络连接中断要分别显示。

## 6 提示词的展示与编辑

### 6.1 用户能看到什么

提示词页签默认展示与当前任务直接相关、可编辑的完整说明。用户可以查看官方原版、当前修改版和两者差异，并清楚看到“官方模板”“已修改”“我的模板”等状态。

“查看本次完整指令”展示本轮实际使用的 Agent 行为说明、任务提示词、被调用教学工具的提示词、工具说明与材料引用。每一步也可查看对应调用的指令记录。展示内容须来自实际执行记录，不从最新模板重新拼出一份看似相同的提示词。

模型接口实际返回的思考文本如有提供，允许完整查看；未提供时明确显示未返回，不虚构思考过程。API 密钥、连接令牌和其他用户数据不属于提示词展示内容。

### 6.2 编辑范围与生效规则

| 操作 | 生效范围 | 用户可见反馈 |
| --- | --- | --- |
| 修改当前任务提示词 | 当前任务的下一次执行 | 自动保存，显示尚未执行的修改 |
| 另存为我的模板 | 未来可复用的个人模板 | 命名、来源版本、保存成功 |
| 恢复官方模板 | 当前编辑副本 | 展示将被替换的修改，允许撤销 |
| 修改 Agent 行为说明 | 本任务可编辑的行为策略 | 与任务提示词分区，明确停止条件和工具选择偏好 |
| 查看已运行步骤 | 该步骤当时的指令 | 只读快照，不能修改已经发生的记录 |

运行期间直接编辑提示词只更新待执行版本，不暗中改变正在进行的模型调用。用户选择“从下一步应用”后，系统记录配置变更；当前调用结束或被停止后，新步骤采用新版本。需要重新处理旧成果时使用“用新要求重新执行”，保留旧结果。

即时补充要求走对话输入，显示“已接收／下一步生效／已生效”。它与提示词编辑引用同一份任务配置，不能形成两套互相矛盾、用户无法追踪的要求。出现实质冲突时说明冲突点，让用户选择适用版本。

用户可自由表达偏好，平台只校验变量、参数和可执行性，不把编辑器变成必须填写固定评分标准的表单。提示词不承担身份权限、工具授权或数据访问控制。

## 7 工具库与可修改工具

工具库按用户能完成的事情组织，例如“查材料”“找试题”“检查文本”“生成教学内容”“搜索网络”。每个工具显示能力说明、输入、结果形式、数据来源、是否联网、是否可用，以及当前任务是否启用。

| 工具类型 | 用户可修改内容 | 产品边界 |
| --- | --- | --- |
| 教学提示词工具 | 指令正文、适用材料、输出要求、个人名称与说明 | 官方版本保留，修改形成个人副本，可独立试运行 |
| 材料查找与正则 | 查找范围、表达式、匹配选项、结果数量或分页 | 返回定位和匹配上下文；无匹配、无效表达式、超时分别说明 |
| 词表与结构检查 | 词表、检查对象、规则选项 | 检查结果来自确定性执行，不让模型伪造工具结果 |
| 高考试题库 | 年份、地区、题型、关键词等服务实际支持的筛选项 | 展示真实来源、覆盖范围与缺失信息，不承诺尚未接入的数据 |
| 网络搜索与 MCP 工具 | 启停、允许的查询范围、服务开放的参数 | 展示调用和来源，连接配置与密钥分开管理 |

修改工具说明不能改变实际执行能力。参数字段与执行端必须一致；不支持的参数在配置或试运行时给出明确错误。底层执行代码不作为普通教师的编辑内容，开发者扩展单独设计。

MCP 的连接配置位于管理后台独立的 Agent 标签。管理员填写地址与令牌、测试连接、读取工具列表、选择搜索工具，并配置查询字段和固定参数。用户前端只显示“网页搜索”开关和数据流向说明，不展示 MCP 地址、令牌或服务参数表。没有配置服务时明确显示“未接入”。首轮接入只读搜索，使用 Streamable HTTP 协议；用户自带连接属于后续扩展。

工具必须在本任务启用后才能调用。工具被关闭时阻止后续调用；已经在执行的调用展示其状态和是否能取消。常规只读工具在既定范围内自主执行，不逐次弹出确认；新增外部服务或将未授权材料发送到外部服务时先说明用途和范围。

## 8 执行过程与用户控制

Agent 根据目标决定何时查材料、调用教学工具、搜索、检查或生成成果。界面不要求用户观看内部命令语言，也不要求为每一步手动审批。需要用户参与的情况应当具体：材料缺失、目标冲突、工具权限不足或预算用尽。

过程主视图显示简短但有信息的进度：当前在处理哪份材料、调用哪个工具、得到什么关键发现、下一步要做什么。工具活动可以展开查看输入、返回结果、来源和错误；大返回值提供全文入口，不挤满主对话。

完整思考、完整指令和工具结果使用独立详情阅读区，支持全文查找、复制和下载。默认折叠详情只是展示选择，不能意味着内容被丢弃。用户向上阅读时停止自动追随，出现新内容用提示条告知。

| 状态 | 用户看到什么 | 可执行操作 |
| --- | --- | --- |
| 准备中 | 可编辑的目标、材料、提示词和工具 | 开始、保存、离开后恢复 |
| 排队中 | 已接收、等待开始 | 取消本轮 |
| 执行中 | 当前活动、进度、实际可得的用量 | 补充要求、查看成果、停止 |
| 等待补充 | 缺少的具体信息和已完成内容 | 回答、补材料、结束 |
| 正在停止 | 已收到停止请求，正在结束当前活动 | 查看已保存内容，避免重复提交 |
| 已停止 | 停止位置、已生成内容、可继续范围 | 继续、新开一轮、导出 |
| 执行结束 | 成果及检查状态 | 审阅、继续修改、导出 |
| 执行异常 | 失败步骤和已保留成果 | 重试失败步骤、换配置继续 |

关闭页面、切任务、刷新或手机进入后台只断开当前视图，不等于停止任务。重新打开恢复服务端状态；浏览器与服务器失联时显示“连接已中断，任务状态待同步”，不能直接认定执行失败。

停止后不得继续自动排入新调用。不能中断的外部请求如实标示，返回后仍保存可用结果，但不擅自推进流程。预算耗尽时保留部分成果并说明继续执行需要什么，不以反复重试耗尽全部额度。

## 9 成果与质检

### 9.1 成果独立阅读和编辑

成果是工作区中的独立对象，不需要从对话日志中复制整理。可按文档、讲义或其他已支持的类型呈现；生成中的版本标为草稿，明确区分完整、待补全和执行中断。

用户可以手动修改成果，形成新版本。Agent 对同一成果的后续修改必须基于明确的版本；如果用户已经编辑出新版本，旧执行不能覆盖它，而应产生可比较的候选稿。

提供完整复制、项目已有格式的导出和来源查看。复制与导出读取完整成果，不读取当前屏幕已渲染的片段。超长内容的阅读优化不能改变导出结果。

### 9.2 开放式审阅

质检不要求用户先制定复杂评分表。默认建议在首次成果完成后做一次开放式审阅，提出真正影响使用的问题并展示依据；用户可关闭审阅、单独发起审阅，或补充自己的检查重点。短问答和纯检索结果不强制追加一轮质检。

审阅必须理解本轮实际的目标、材料范围、工具要求和成果。工具要求跳过的听力不应被判为缺失；缺少原文时不能要求生成器补造原文；允许创作的题目也不能仅因材料中没有就判为错误。

每条意见尽可能给出成果位置、问题、依据和建议。无法核实的内容与确定错误分别标注。审阅模型的意见是建议；用户可以忽略、要求复核或选中若干意见进行修改。

首版建议默认“给出意见，由用户选择是否修改”。用户可开启自动改进，但每轮都生成候选版本并保留旧稿；能查看差异和恢复，不能把模型的一次“通过”当作无风险保证。自动改进需有轮数及预算上限，遇到无法解决的分歧停止并展示问题。

### 9.3 状态与版本必须说清楚

“执行结束”“审阅完成”“存在待处理意见”和“用户采用”分别记录。没有经过审阅不能显示“质检通过”；达到次数上限不能自动转换成通过。

局部修改与整篇重写均是可用操作，由任务性质决定。匹配失败、调用失败和输出解析失败不构成整篇重写的理由。所有修改都有明确输入版本，新版本的产生不销毁旧版本。

版本比较要能识别整节删减、题号变化、新增材料和来源变化。候选稿尚在生成时可预览，但不可显示为可采用的完整版本。用户可随时返回原稿，不需要重新生成来恢复丢失内容。

## 10 长内容与性能

完整保存、按需传输、按可视范围渲染是三件独立的事。运行日志、思考、工具结果和成果须有可恢复的完整数据；前端不应因显示进度而反复读取、写入或重排整份任务。

增量更新后，已完成步骤与未变化的内容保持稳定。折叠区不持续构建长文 DOM；展开后支持分块或虚拟滚动，滚动到历史部分能继续获取原文。用户读旧段落时，新内容到达不改变阅读位置。

新增思考不会触发全部历史任务写盘、全文搜索索引重建和跨设备全文同步。初次打开长任务先显示导航、状态和可读部分，后续按需补齐；同步期间不锁住输入和停止按钮。

模型输出达到上限时，系统可以在上下文允许且任务需要时续写或拆分处理。无法完成则标记待补全、保留已生成内容，不能把截断当正常结束。上下文摘要用于帮助模型继续工作，用户可读的原始记录仍然保留。

性能目标见第 13 节，需要通过真实浏览器测量；概念图不代表已验证的性能。

## 11 任务保存与跨设备恢复

任务运行、配置版本、材料和成果以服务端记录作为恢复依据，本地存储用于输入草稿和读取缓存。任务与当前身份关联；沿用使用码时要明确同一使用码的跨设备访问范围，不混入其他身份的记录。

提示词与任务目标自动保存，显示保存中、已保存和离线待同步。网络失败时保留本地修改，恢复后若存在另一设备的更新，展示冲突副本供选择，不能按最后到达时间静默覆盖。

删除任务、材料或模板前说明影响范围，任务运行中删除需处理停止与保留关系。任务数据保留期限在开始前可查，并提供导出；具体期限与存储成本需在上线前确定。

## 13 验收条件

### 13.1 多设备与交互

测试矩阵至少覆盖 1920×1080、1440×900、1366×768、1280×720、1024×768、768×1024、390×844、360×640 的 CSS 视口；另测 200% 浏览器缩放、系统缩放、手机横屏与软键盘展开。使用真实桌面浏览器和至少一台 iOS、一台 Android 设备，记录浏览器版本和硬件。

所有尺寸都能完成新建、上传、编辑提示词、选择工具、开始、补充、停止、查看来源、比较版本和导出。窗口尺寸变化后保留输入、选中任务、页签、版本与阅读位置。页面主体无横向溢出，编辑区与主操作不被键盘或安全区遮挡。

### 13.2 长内容压力场景

建议固定测试数据包含单次 10 万字符思考、累计 200 条活动、30 万字符成果及多轮追加。测试数据必须覆盖中文、英文、表格、长行和 Unicode 字符，并包含运行中、已完成和恢复后的状态。

在记录配置的普通四核、8 GB 内存笔记本及测试手机上，连续运行 30 分钟；常见点击和输入的响应时间目标为 P95 不超过 200 ms，不出现进度刷新造成的反复一秒级卡死。打开全文、滚动、切页签和停止均在测试范围内，不能只测默认折叠状态。

网络传输应能证明已经接收的完整旧日志不会随每次心跳重复下发。多次展开、折叠和切换后内存应趋于稳定，无随操作次数持续增长的泄漏。全文复制和下载与保存源数据逐字一致，无静默截头、截尾和中段遗漏。

### 13.3 可靠性与内容质量

| 必测情形 | 验收要求 |
| --- | --- |
| 试卷含听力，但本次要求排除 | 生成和审阅尊重同一范围，不要求补回听力 |
| 试卷缺原文或答案 | 明确缺失或按任务允许的方式推断，不把编造内容冒充原材料 |
| 质检意见本身错误 | 可以忽略或复核；不因意见存在就覆盖正确内容 |
| 补丁失败、重复定位、重写丢节 | 原稿可完整恢复，新稿不能静默覆盖 |
| 用户手动修改与 Agent 同时完成 | 产生可比较版本，不丢用户编辑 |
| 输出达到长度上限 | 续写或标记待补全，不假报完成 |
| 刷新、断网、移动端后台、服务重启 | 恢复正确任务状态，无重复创建、扣费或丢失已保存版本 |
| 运行中修改提示词或关闭工具 | 显示生效边界，下一步使用正确配置，旧步骤快照不变化 |
| 检索无结果、来源访问失败 | 如实报告，不生成伪造题库条目、搜索结果或引用 |
| 打开历史任务 | 查看的是当时指令、配置和成果，不是当前模板替换后的版本 |

至少建立 20 个真实教学任务样例，覆盖整卷、多篇、长文、缺材料、用户改提示词、查题和上述失败样例。对照普通工具和旧 Agent 结果，由教师或产品负责人盲评正确性、覆盖度、可用性与修改后的退步情况。自动审阅模型不能成为唯一质量裁判；出现未经允许删内容或编造来源的案例阻止发布。

## 14 体验指标

关注首次任务完成率、开始前配置耗时、成果采用与导出率、候选稿被拒绝或退回原稿的比例、质检误报率、恢复成功率，以及分设备的交互延迟和卡死反馈。拆分“模型失败”“工具失败”“用户主动停止”和“页面失联”，避免把所有未完成任务混在一起。

不把思考字数、调用工具数量和执行步骤数作为产品成功指标。透明的过程要帮助用户判断工作是否可靠，而不是制造忙碌感。

## 15 上线前需要确认的产品选择

| 选择 | 本版建议 | 影响 |
| --- | --- | --- |
| 默认审阅方式 | 开放式意见，用户选择修改；自动改进可选 | 自动化程度、调用成本与误改风险 |
| 题库首批范围 | 先明确数据来源与可检索字段，再确定年份和地区 | 检索体验与结果可信度 |
| MCP 首批范围 | 平台配置的只读搜索；个人连接随后开放 | 接入速度、凭据管理和外部数据范围 |
| 任务与原始过程保留期限 | 成果、材料、过程分别定义，并向用户明示 | 存储成本、跨设备恢复与隐私预期 |
| 计费与预算 | 开始前显示本轮规则、额度和停止条件；沿用规则需经成本验证 | 用户预期与长任务可持续性 |
| 旧任务过渡 | 保留阅读与导出，不把不兼容状态强行续跑 | 重写切换期间的可用性 |

这些选择不改变核心体验要求：用户知道 Agent 收到了什么、被允许做什么、实际做了什么，也能在任何设备上检查和修改结果。
